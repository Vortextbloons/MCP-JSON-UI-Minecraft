Technical Specification: Minecraft Bedrock JSON UI MCP Server1. Introduction and PurposeThe purpose of this Model Context Protocol (MCP) server is to provide an AI agent with the ability to safely and accurately author, validate, and iterate on Minecraft Bedrock JSON UI files. Bedrock UI operates on an undocumented, complex proprietary engine with a strict JSON syntax. Often, AI agents hallucinate properties or miss namespace requirements, which leads to silent UI failures or game crashes.By creating a feedback loop via this MCP server, the AI can:Reference official schema limitations and valid Data Bindings via a provided MCP Resource.Draft the JSON UI code.Validate the generated output using the validate_ui_contract MCP Tool against strict Go-based schema rules.Self-Correct based on programmatic error logs provided by the server before returning the final file to the user for deployment in a Resource Pack.2. Core Requirement: Validation LogicThe Go server will use the jsonschema library to parse the generated UI JSON and test it against the strict layout above.Gopackage mcp

import (
	"bytes"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/santhosh-tekuri/jsonschema/v5"
)

// Validate Bedrock UI JSON against our strict Schema definition
func ValidateBedrockUIContract(uiJson string) ([]string, error) {
	compiler := jsonschema.NewCompiler()
	
	// Load the schema from a string (in-memory) or embedded file.
	// For the spec, schemaBytes is the []byte form of the JSON above.
	if err := compiler.AddResource("bedrock_ui.json", bytes.NewReader(schemaBytes)); err != nil {
		return nil, fmt.Errorf("failed to load schema: %w", err)
	}

	schema, err := compiler.Compile("bedrock_ui.json")
	if err != nil {
		return nil, fmt.Errorf("failed to compile schema: %w", err)
	}

	// Parse incoming JSON
	var v interface{}
	if err := json.Unmarshal([]byte(uiJson), &v); err != nil {
		return []string{fmt.Sprintf("Syntax Error: Invalid JSON structure. %v", err)}, nil
	}

	// Validate JSON against Schema
	err = schema.Validate(v)
	if err != nil {
		var errorMessages []string
		if validationErr, ok := err.(*jsonschema.ValidationError); ok {
			// Flatten and format validation errors for the AI
			for _, cause := range validationErr.Causes {
				errorMessages = append(errorMessages, fmt.Sprintf("Logic Error at %s: %s", cause.InstanceLocation, cause.Message))
			}
			return errorMessages, nil
		}
		return []string{err.Error()}, nil
	}

	// Custom Engine Logic Checks (Examples)
	// Even if schema-valid, Bedrock has specific quirks.
	var customErrors []string
	if !strings.Contains(uiJson, "\"namespace\"") {
		customErrors = append(customErrors, "Logic Error: Missing required 'namespace' declaration at root level.")
	}

	return customErrors, nil
}

6. Core Requirement: The Tool (validate_ui_contract)To close the loop, the MCP Tool is defined so the AI can pass its synthesized JSON and immediately retrieve errors.Tool JSON-RPC DefinitionJSON{
  "name": "validate_ui_contract",
  "description": "Validates Minecraft Bedrock JSON UI string against Bedrock engine constraints. Returns syntax or logical errors, such as missing namespaces, invalid layout strings, or unsupported bindings. Always call this before giving the user the final code.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "ui_json": {
        "type": "string",
        "description": "The fully stringified JSON of the Bedrock UI element you want to test."
      }
    },
    "required": ["ui_json"]
  }
}
Go Tool HandlerGo// Handles the "validate_ui_contract" tool invocation within the MCP standard transport loop
func handleValidateUITool(params map[string]interface{}) (map[string]interface{}, error) {
    uiJson, ok := params["ui_json"].(string)
    if !ok {
        return createErrorResponse("ui_json must be a string"), nil
    }

    errorsList, err := ValidateBedrockUIContract(uiJson)
    if err != nil {
        return createErrorResponse(fmt.Sprintf("Internal Validation Error: %v", err)), nil
    }

    if len(errorsList) == 0 {
        return map[string]interface{}{
            "content": []map[string]interface{}{
                {"type": "text", "text": "✅ Success: UI Code passes Bedrock Schema and Logic constraints."},
            },
        }, nil
    }

    // Join and format errors to give AI clear context
    formattedErrors := "❌ Validation Failed with the following errors:\n"
    for idx, e := range errorsList {
        formattedErrors += fmt.Sprintf("%d. %s\n", idx+1, e)
    }

    return map[string]interface{}{
        "content": []map[string]interface{}{
            {"type": "text", "text": formattedErrors},
        },
    }, nil
}
7. The Feedback LoopHere is how the system forces the AI to iterate and generate pristine resource pack data:User Prompt: "Make a custom inventory panel that displays the player's name and an item."AI Action 1 (Read Docs): The AI invokes the ui_reference MCP resource to locate the correct bindings (#playername, #item_id_aux).AI Action 2 (Generate Code): The AI generates a Draft JSON string containing a panel with nested label and image types.AI Action 3 (Validate): The AI executes the validate_ui_contract tool with its drafted JSON.Server Processing: The Go server catches a missing namespace and reports back: ❌ Validation Failed: Logic Error: Missing required 'namespace' declaration at root level.AI Action 4 (Self-Correct): The AI patches the JSON payload, adding "namespace": "custom_inventory".AI Action 5 (Re-Validate): Tool returns ✅ Success.Final Output: The AI presents the perfectly validated code block to the user, guaranteed to parse in Minecraft Bedrock
