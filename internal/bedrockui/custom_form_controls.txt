=== CUSTOM FORM CONTROLS (MODAL FORM) REFERENCE ===

JSON UI renders fields provided by the behavior pack's ModalFormData call.
Labels, values, defaults and options are not created by declaring JSON UI templates.
Source: https://github.com/Mojang/bedrock-samples/blob/main/resource_pack/ui/server_form.json

Prefer inheritance from server_form.custom_form, custom_form_panel,
custom_form_scrolling_content and generated_contents to preserve scrolling and
submission. The scrolling content instantiates generated_form and a submit button.
A root submit_button definition alone does not display a button.

Factory mappings may reference these vanilla templates:
label -> @server_form.custom_label
toggle -> @server_form.custom_toggle
slider -> @server_form.custom_slider
step_slider -> @server_form.custom_step_slider
dropdown -> @server_form.custom_dropdown
input -> @server_form.custom_input

Example custom widget definition:
"custom_toggle@server_form.custom_toggle": {}

The generated_contents collection container uses a factory property named buttons,
collection_name custom_form, and #custom_form_length mapped to #collection_length.
Retain all mappings supported by the target game version when overriding it.
Bare toggle/slider/edit_box types do not provide vanilla visuals and response wiring.
$pressed_button_name and $button_text are template variables; a bare button needs
actual button_mappings and child visuals, or inheritance from a button template.

Do not add # to the vanilla toggle_name / slider_name identifiers. Names of engine
bindings such as #custom_toggle_state do use #. For exact variable, binding and
collection names, inspect the target game's vanilla server_form.json.

Register custom UI files in the resource pack's ui/_ui_defs.json and wire them
through server_form. A custom namespace by itself does not open a screen.
